## Change and source safety

After a completed, drained and released native source probe returns a recognized
Windows exception status, an M4A gets one stream-copy recovery in a guarded owned
scope. The copy is re-probed and uses its own stream index. Strict sample-time
decoding of the original supplies an independent duration check before the
existing encode/validation/publication transaction. Original identity, relative
naming/date, metadata, cover, 64 kbps default and no-overwrite protection remain.

A smaller source query requests the title tags actually consumed by the planner;
FFmpeg still maps source metadata. Explicit literal JSON date parsing is used
where supported. This fixes the observed current-PowerShell timestamp conversion
failure. Failed files are named in the final summary, and bounded native stage,
exit, stderr and recovery evidence remains in the existing local log/manifest.
