## Bounded work

1. Keep a human-readable local log with actual app/tool versions, selected policies, per-file errors, timing and final result.
2. Write a compact local CSV or JSON manifest mapping inputs to outputs/outcomes/duration/bytes. CSV must roundtrip Unicode/quotes/newlines and avoid formula execution surprises.
3. Count outcomes consistently and handle manifest/log write failure explicitly; do not claim full success when required run records cannot be written.
4. No telemetry or automatic uploads; public issue template must ask users to redact paths/content. Keep raw personal runtime logs out of Git.

## Acceptance and evidence

- **A35 — Diagnostics persist locally:** Useful native error details survive in the run log with tool/app versions, timings and final outcome; large native output is bounded; logs are not uploaded. Method: failure fixtures + log inspection.
- **A36 — Manifest correctness:** One row per discovered candidate outcome; Unicode, commas, newlines and formula-like text safely represented; input/output paths, duration, bytes and failure reasons are traceable. Method: structured roundtrip and totals tests.
- **A37 — Accurate outcome totals:** Discovered/converted/failed/skipped/cancelled counts reconcile; actual bytes and elapsed time are reported; scan exclusions are distinguishable from successful conversions. Method: mixed outcomes tests.
