## Implementation and acceptance

CreateNew reserves the fixed sibling `.AudioFileForPhone-<32 hex>.partial` after
literal canonical containment, reparse and complete path-budget checks. A retained
ReadWrite handle without Delete sharing guards pathname ownership during encoding,
probe and decode. Volume/file-index identity checks gate promotion and cleanup.
FFmpeg receives `-y` only for that owned file and `-f mp3` explicitly. A nonempty
MP3 must contain exactly one MP3 audio stream at the selected bitrate, and exactly
one attached JPEG only when an explicit cover was requested. Container bitrate
does not establish audio bitrate.

Finite positive source audio duration is mandatory. Container duration is a
fallback only for absent/N/A selected-stream duration; invalid values fail before
encoding. Probe, source and decoded durations must agree within a fixed 0.35 s.
Full audio decode with fatal error handling and validation-only sample-count
timestamps detects truncated/corrupted payloads despite plausible Xing headers.
This extra read/decode pass changes no published audio processing. No long-file
performance result is claimed.

Only validated output reaches two-argument File.Move, which refuses overwrite.
A concurrent final target fails that file with the original planned mapping.
Cleanup removes only the matching current partial after child/process use ends;
changed identity or unproved exit retains a clearly incomplete path and diagnostic.
Postpublication log failure explicitly reports the published path, stops with
exit 1 and preserves completed output instead of misclassifying it or double counting.
