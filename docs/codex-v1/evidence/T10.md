## Implementation and acceptance

Selected script contract: 0 / Completed for all supported snapshot files succeeding;
2 / CompletedWithFailures for a completed batch with per-file failures; 1 /
FailedBeforeConversion or Failed for preflight, empty scan, setup or fatal failure.
The native probe and transaction boundary catches ordinary file errors and continues
independent files. Count each file once after its result, with success only after
T09 publication. Later diagnostics cannot reclassify a published file. A log error
is fatal and reports the primary file outcome plus secondary diagnostic cause.
Progress display failure warns and continues. Final console summary includes total,
processed, converted, failed, not_processed, scan_excluded, unsupported, elapsed
seconds, available output/log paths and exit code. Existing text-log Summary totals
remain for compatibility; normal runs add a RESULT record.

Unsupported counts cover ordinary files in visited directories. Scan exclusions
count skipped entries, including entire excluded directories; neither contributes
to conversion failures. A reservation can leave a marker-only scope after setup
fails before returning its object. The original error preserves that exact scope
and token, while final fallback messages say the location is unavailable rather
than falsely implying nothing was created. Production never deletes that run.

BAT accepts exactly one nonempty argument, preserves STA and disables delayed
expansion. Separate launch branches capture child errorlevel immediately and
return it after pause. Messages distinguish 0, 1, 2, reserved 130 and unknown
nonzero codes. Source processing, default 64 kbps CBR, supported formats, Music
default, layout, metadata, naming, staging and publication invariants remain.
